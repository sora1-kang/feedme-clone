# URL을 Markdown으로 변환

웹 페이지 URL을 붙여넣으면 본문만 Markdown으로 뽑아 보여 주고, 복사하거나 파일로 받거나 ChatGPT·Claude 새 대화로 넘길 수 있게 한다.

## 사용자에게 보이는 결과

1. 사용자가 URL을 입력창에 붙여넣고 변환을 실행한다.
2. 변환이 끝나면 페이지 제목과 저자가 머리말로 나오고, 그 아래에 본문이 렌더링된 Markdown으로 나온다.
3. 사용자는 결과를 복사하거나 `.md` 파일로 내려받거나, ChatGPT 또는 Claude 새 대화로 넘긴다. 넘길 때 프롬프트를 고를 수 있다.
4. 지우기 버튼을 누르면 입력과 결과가 함께 초기화되어 처음 상태로 돌아간다.
5. 다크모드 토글로 화면 테마를 바꿀 수 있다.

## 승인된 화면

[prototype.html](prototype.html)이 승인된 화면과 상호작용의 기준이다. 화면 구성, 상태(기본, 변환 중, 결과, 저자 없음, 오류), 내보내기 영역의 배치와 안내 문구는 이 파일을 따른다. 프로토타입은 참고용이며 구현 코드가 아니다. 클립보드, 다운로드, 새 탭 열기는 프로토타입에서 시뮬레이션이다.

## 범위

- URL 입력, 지우기, 변환, 결과 표시
- 복사하기, `.md` 다운로드
- ChatGPT·Claude로 열기와 프롬프트 선택
- 다크모드 토글

## 수용 기준

- 공개된 일반 문서형 페이지의 URL을 넣으면, 제목과 저자(있을 때)가 머리말에 나오고 본문이 렌더링된 Markdown으로 나온다.
- 저자 정보가 없는 페이지는 저자 항목만 생략하고 제목과 본문은 그대로 나온다.
- 변환하기는 화살표 아이콘 버튼, 지우기는 X 아이콘 버튼이다. 글자가 없으므로 둘 다 "변환하기", "지우기"라는 접근성 이름과 툴팁을 가진다. 변환 중에는 화살표가 회전 아이콘으로 바뀌고 버튼이 비활성화된다.
- 지우기를 누르면 입력창, 결과, 오류 표시가 모두 비워진다.
- 잘못된 URL, 접근할 수 없는 페이지, 본문을 찾지 못한 페이지는 입력창 아래에 원인이 드러나는 오류로 표시되고 이전 결과는 남지 않는다.
- 입력이 비어 있거나 `http://`, `https://`로 시작하는 주소 형식이 아니면 서버에 요청하지 않고 그 자리에서 원인이 드러나는 오류를 보여 준다.
- 내려받기와 AI로 열기를 누르면 결과 영역 안에 한 줄 안내가 나온다. 내려받기는 저장된 파일 이름을, AI로 열기는 본문을 복사하고 새 대화를 열었다는 사실과 채워진 프롬프트를 알려 준다.
- 변환 중에는 진행 중임이 보이고 같은 요청을 중복해서 보낼 수 없다.
- 복사하기를 누르면 Markdown 본문 전체가 클립보드에 들어가고, 복사됐음이 화면에 표시된다.
- 다운로드는 `.md` 파일로 저장되며 내용은 화면의 Markdown과 같다. 파일 이름은 페이지 제목에서 만든다.
- 프롬프트 프리셋은 "요약해줘", "한국어로 번역해줘", "쉽게 설명해줘" 세 가지와 "직접 입력"이다. 아무것도 고르지 않을 수 있다.
- "직접 입력"을 고르면 프리셋 옆에 텍스트 입력창이 나타난다. 입력한 내용은 저장하지 않으며 새로고침하면 사라진다.
- "ChatGPT로 열기" 또는 "Claude로 열기"를 누르면 Markdown 본문이 클립보드에 복사되고, 해당 서비스의 새 대화가 새 탭으로 열린다. 프롬프트를 골랐다면 새 대화 입력창에 그 프롬프트가 채워져 있고, 고르지 않았다면 빈 대화가 열린다. 사용자는 붙여넣기만 하면 된다.
- 본문 길이와 관계없이 열기 동작은 같은 방식으로 동작한다. 본문을 URL에 싣지 않는다.
- 좁은 화면에서도 입력, 결과, 내보내기 동작이 숨겨지지 않고 순서대로 쌓인다.
- 다크모드 토글은 라이트와 다크를 바꾸고, 처음에는 시스템 설정을 따른다. 입력, 결과, 오류, 로딩 상태가 두 테마 모두에서 읽힌다.

## 확정한 제약과 이유

- **변환은 defuddle 라이브러리로 한다.** 사용자의 필수 요구다. 호스팅 서비스 defuddle.md는 추가 요청에 API 키가 필요하다고 문서에 나와 있어 쓰지 않는다.
- **페이지 가져오기와 변환은 서버 쪽에서 한다.** 임시 환경에서 확인한 결과, 대상 사이트가 CORS 헤더를 주지 않아 브라우저가 임의의 URL을 직접 가져올 수 없다. Node에서는 DOM 구현체(jsdom)가 필요하며, `defuddle@0.19.5`와 `jsdom@30.0.1`로 실제 페이지에서 `title`, `author`, Markdown 본문이 나오는 것을 확인했다.
- **AI 서비스로 넘길 때 본문은 클립보드로, 프롬프트는 새 대화로 넘긴다.** 본문을 URL 쿼리에 실으면 긴 글에서 잘리거나 실패하고, 짧은 글과 긴 글의 동작이 갈라진다. 클립보드 방식은 길이와 관계없이 같게 동작한다. 사용자가 확정했다.
- **클립보드에는 본문만 넣는다.** 프롬프트는 새 대화 입력창에 이미 채워지므로 클립보드에도 넣으면 한 번 더 들어가 중복된다.
- **UI는 기존 결정 계약 [ui-composition](../../decisions/ui-composition.md)을 따른다.** shadcn 컴포넌트와 semantic token으로 구성하고, 로딩·오류·빈 상태·성공 상태를 정상 화면과 함께 설계한다.

## 가정 (반대하시면 바꾼다)

- 복사하기 버튼은 프롬프트 없이 Markdown 본문만 복사한다. 프롬프트는 AI로 열기에만 쓴다.
- 변환 결과와 프롬프트 선택은 서버나 브라우저에 저장하지 않는다. 새로고침하면 처음 상태가 된다.
- 한 번에 URL 하나만 변환한다.
- 로그인이 필요한 페이지, 스크립트로 본문을 그리는 페이지는 지원하지 않으며, 이 경우 본문을 찾지 못한 오류로 처리한다.
- 다크모드 선택은 이 브라우저에서 기억해도 되지만, 기억하지 못해도 동작은 같다.

## 범위 밖

- 여러 URL의 일괄 변환, 변환 이력, 로그인과 계정, 결과 저장
- AI 서비스 호출 자체. 새 대화를 열어 줄 뿐 응답은 가져오지 않는다.
- PDF, 로그인 필요 페이지 같은 비문서형 입력

## 보류한 항목

- 없음.

## 남은 위험

- **ChatGPT·Claude의 새 대화 URL이 프롬프트를 쿼리로 받는지는 확인하지 못했다.** 두 서비스는 쿼리로 입력창을 채우는 주소를 지원하는 것으로 알려져 있지만, 로그인이 필요해 이번 세션에서 검증하지 못했다. 동작하지 않으면 프롬프트도 클립보드에 함께 넣는 방식으로 바꿔야 하며, 그때 중복 문제를 다시 정해야 한다.
- 클립보드 쓰기는 브라우저 권한이나 보안 컨텍스트에 따라 실패할 수 있다. 실패하면 사용자에게 알려야 한다.
- 사이트에 따라 서버의 가져오기 요청이 차단될 수 있다. 이 경우 접근 불가 오류로 처리한다.
